# 进展整理与断点恢复

## 状态分层

- **操作状态：** 未开始、填写中、已填写未确认保存、已保存、待人工核验、已获当前版本投递授权、已投递待核实、投递已核实、阻塞。
- **招聘阶段：** 以真实平台/通知为准，如已申请、筛选、笔试、面试、Offer、未通过、撤回、未知。填写完整、自动化任务成功或已授权不等于招聘方收到申请。
- 本人自报、历史记录、工具记录、当前官网结果分别标来源；没有查到记录不等于没有投过，没有获得结果不报“0 条”。等待时间不能推断未通过。

## 只整理进展时

读取用户提供的记录或本轮已获授权的数据源；只查指定公司/范围。在线结果含分页时，说明当前覆盖范围，不默认为完整历史。冲突保留来源和核验时间，不凭列表顺序决定最新。

输出 `公司/岗位 | 当前状态与来源日期 | 已知截止/面试安排 | 下一步`。只有通知或平台明确给出日期和入口才列具体安排；不擅自更新线上阶段、撤回申请、催 HR 或创建自动跟进。

## 需要跨会话续填时的最小恢复记录

在当前任务本地工作目录记录；用户明确要求维护长期投递表时才更新指定文件。恢复记录不同于候选人事实库，不把历史状态写成个人事实。

每个目标分别保留：

```text
目标：公司、职位 ID/名称、城市、官方岗位与编辑页链接
版本：简历/附件绝对路径和版本标识；用户确认范围
阶段：操作状态；招聘阶段与依据（若已取得）
区块：已回读保存的记录数量、尚未确认保存的批次
证据：核验时间、成功提示/回读摘要或必要截图指针
问题：缺失事实、方向冲突、待授权动作与依赖
下一步：从哪个区块/记录续填；是否仍待人工核验
```

只存恢复所需信息，不复制密码、Cookie、Token、完整证件号或不必要的家庭资料。含凭据的签名链接不持久化；用普通入口和恢复步骤替代。用户只问进展时直接对话交付，不额外建文件。

## 恢复顺序

1. 打开当前真实页面，核对公司、岗位、城市、所选简历版本及已有申请；历史编辑链接或标签 ID 可能失效。
2. 回读记录数量、已保存内容和当前弹层；以网页现状确定哪些动作已完成，不盲信上次调用结果。
3. 对不一致部分标差异；确认没有重复记录后，从未完成处续填。未明确失败不重放新增或投递。
4. 人工核验/授权必须对应目标和当前版本；记录变更后不能沿用旧版授权。最终结果仍按 SKILL.md 核验。
