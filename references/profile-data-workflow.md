# 简历资料添加与更新流程

本流程用于把候选人新提供或新确认的事实写入本地资料文件。它不替代网页填写时的逐项核对。

## 1. 识别资料归属和变更范围

- 确认本次资料属于哪位候选人；不要把当前本地 profile 套用给其他人。
- 记录本次新增、纠正、作废的字段和适用范围。只修改相关记录，不重写无关资料。
- 用户在当前任务中的明确纠正优先于旧资料；无需重复索要已经明确给出的信息。

## 2. 按来源记录事实

每项事实尽量保留以下信息：

- 字段和值；
- 来源类型或本地来源指针；
- 来源记载的日期精度；
- 状态：用户确认、凭证支持、待核实或推导；
- 记录/确认时间，以及适用的网站或任务范围（如有限定）。

优先顺序为：当前用户明确提供或纠正的内容、用户为本次任务指定的最新定稿、原始凭证及其他适用材料、较早的参考资料。修改时间仅作辅助，不能单独决定哪份资料最新。冲突无法依据来源解决时，不用常识猜测。

获奖事实采用 [获奖来源与时间规则](source-guide.md#获奖来源与时间规则)：以保存的获奖资料表及凭证为基准，不能将最新简历或解析结果中多出的奖项自动写入 `awards`。新增或纠正需有新凭证或用户对具体奖项事实的明确补充，并分别记录来源及日期精度；一般性简历定稿确认不能充当奖项确认。

## 3. 分开保存事实、映射和临时决定

- 教育、工作/实践、校园活动、奖项、论文等逐条记录；不要把不同阶段合并成一条。
- 原始事实与表单字段映射分开保存。网站下拉选项不能反过来改变凭证记载的事实。
- 日期按原始精度保存；若用户明确批准补全日期，另外记录补全依据及适用范围。不能把某次填报的选择推广成通用规则。
- 未确认内容标为未知或待核实，不伪装成事实。旧页面状态另记核验日期，不覆盖资料事实。

## 4. 最小化敏感信息

- profile 和凭证只保存在用户指定的本地位置；不要将身份证号、家庭资料、联系方式、证件照片或简历原文复制进公共示例或 GitHub。
- 对需要核对但不需长期存储的高敏字段，优先保存来源指针，不保存完整值。
- 公开发布时使用 user-profile.example.json；真实 user-profile.json 必须留在本地，并由 .gitignore 排除。

## 5. 写入后验证

- 只修改本次确认的字段；保留其他已确认内容。
- 解析 JSON，检查记录数量、字段类型、引用来源和日期依据。
- 检查示例、截图和说明中没有混入真实个人信息；确认私有文件没有被加入暂存区或跟踪。
