# 日期控件探索与北森实测

## 适用范围

本参考提炼自北森 Phoenix 日期控件的历史操作经验，仅说明日级控件的已观察路径；不保证所有网站或精度一致。使用时以当前页面和工具文档为准。

## 首次控件先探索，已验证路径批量复用

以下探索用于当前页面尚未验证的控件。同一区块结构一致、交互路径已验证的日期字段按 SKILL.md 批量填写并集中回读；不为每个日期重复完整探索。新弹层内容、实时索引或联动变化仍需读取后再操作。

1. 按当前区块、记录及字段名称唯一定位，读取字段当前值与可见 DOM 属性。外层即使包含 `input`，也可能只用于展示或搜索；不要直接假定它是日期编辑入口。
2. 点击一次展开，立即检查新弹层。区分外层字段、弹层输入框、年/月切换按钮、日期网格与确认按钮；注意弹层可能挂在页面末尾而非字段内部。
3. 存在可编辑日期框时，核实格式和精度，再输入有资料依据的日期并使用控件支持的确认动作。没有可编辑框时，根据当前可见控件探索年/月选择及日期网格，每次切换后检查新状态；这一路径需现场验证，不视为本次已验证。
4. 回读原字段值，确认弹层选择已真正回填；弹层标题、暂时输入值或点击成功不是完成证据。若失败，检查可见格式、范围、禁用日期或未确认状态，有证据后再修正，不绕过控件校验。

## 已验证的 Phoenix 路径

观察到的外层为 `.form-item`，标签为 `.form-item__text`，日期选择器包含 `.phoenix-select`。点击目标日期字段后，页面末尾出现独立的 `input.phoenix-calendar-input`，以及年/月按钮、日期网格和「今天」。弹层输入框支持 `YYYY-MM-DD`；`fill` 后按 Enter，原字段得到日期且弹层关闭。不能把弹层初始显示的日期当作候选人的事实。

以下是操作形状，不是固定工具入口。先加载当前浏览器文档、绑定本任务标签并从当前 DOM 验证这些选择器和匹配数量；不固化浏览器/标签 ID，不用 `.last()` 或全页面同名输入框猜目标。

```javascript
// fieldName 取当前已核验的字段名称；同名字段须先限定所属经历记录。
const field = tab.playwright.locator('.form-item').filter({
  has: tab.playwright.getByText(fieldName, { exact: true })
});
// 先确认 field 匹配唯一，且其中只有一个目标 textbox。
await field.getByRole('textbox').click();
// 在单独状态检查中观察弹层、日期格式及是否可编辑。
```

```javascript
// 仅在当前可见弹层已验证、目标输入框匹配唯一后使用。
const dateInput = tab.playwright.locator('input.phoenix-calendar-input');
await dateInput.fill(confirmedDate);
await dateInput.press('Enter');
// confirmedDate 来自本次适用的已确认资料，不从控件默认值推断。
```

```javascript
// 只读回读原字段，不读框架私有状态，也不通过 evaluate 写值。
const actual = await field.evaluate(element => ({
  text: element.innerText,
  values: Array.from(element.querySelectorAll('input')).map(input => input.value)
}));
// 首次试填核对 actual 与 confirmedDate；路径已验证后的同类字段在区块末集中回读。
```

## 批次大小与超时恢复

- 本次浏览器单步调用多次耗时约 21–23 秒，三个顺序操作约 64 秒；这是本次观测，不是其他环境的固定时延。包含多个顺序操作的整段调用可能先于网页流程超时。
- 默认合并已验证的顺序操作并在区块末回读。仅首次探索、弹层内容变化或超时恢复时，在「展开并观察」「输入并确认」等必要边界拆批；依据实测时延控制批次，不把历史慢调用推广为全程逐字段操作。不添加固定睡眠，不并行输入，不把增加时限当作控件解法。
- 中断后先恢复当前字段值和弹层状态，再继续。例如输入已完成但确认未执行，就检查并完成确认；不能从头重复点击、重复新增，或直接宣称连接失败。

## 保存与持久性证据

- 本次两项日期均经：弹层输入 → Enter → 原字段回读 →「暂存」→ 安全刷新后值仍保留。由此只能确认这两项日期已暂存，不能推断所有必填项完成或已投递。
- 优先以明确成功提示、只读预览或安全重开后的保留值确认保存。重开/刷新前须确认没有不可恢复的未保存输入，并已留存必要恢复信息；不得为验证少数字段刷新含大量未保存内容的长表单。
- 如保留截图，须能看到实际日期字段；截图名称不能替代截图内容核验。证据截图仅保存在用户指定的私有目录，不复制私人字段到通用示例。
- 本方法不改变资料精度规则、最终提交确认要求或其他网站的披露授权。
